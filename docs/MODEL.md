# Модель оценки стоимости квартир (hpwhd)

> Документация по ML-модели сервиса **hpwhd** — оценка рыночной стоимости квартир
> в Казахстане. Готовится к встраиванию в основное приложение банка в виде
> модуля прогнозирования цен на недвижимость.

**Статус:** черновик / собирается
**Версия модели:** ансамбль v2 (55 признаков)
**Валюта результата:** KZT (казахстанский тенге)
**Метрика качества:** Test MAPE 9.64% (hold-out), 12.12% на «живых» объявлениях март–апрель 2026

---

## 1. Цель (Goal)

Дать пользователю **быструю и объективную оценку рыночной стоимости квартиры**
в тенге на основе небольшого набора понятных характеристик объекта.

В контексте банковского приложения модуль решает следующие задачи:

- **Оценка залога** — быстрая ориентировочная стоимость недвижимости при
  ипотечном/залоговом кредитовании.
- **Проверка адекватности цены** сделки (не завышена / не занижена относительно рынка).
- **Клиентский сервис** — пользователь вводит параметры квартиры и мгновенно
  получает оценку цены и «портрет локации».
- **Скоринг и аналитика** — стоимость м² как признак в других банковских моделях.

**Что модель НЕ делает:** это не официальная оценка для нотариуса/суда, а
статистический прогноз рыночного уровня цены с указанием доверительного интервала.

## 2. Термины и определения (Glossary)

| Термин | Определение |
|--------|-------------|
| **MAPE** | Mean Absolute Percentage Error — средняя абсолютная процентная ошибка прогноза. Основная метрика качества. |
| **KZT/m²** | Цена одного квадратного метра в тенге. Базовая величина, которую предсказывает модель; итоговая цена = KZT/m² × площадь. |
| **Ensemble (ансамбль)** | Композиция из нескольких моделей (LightGBM + нейросеть), объединённых мета-моделью Ridge. |
| **LightGBM (LGB)** | Градиентный бустинг над деревьями решений — основной прогнозист (вес ≈ 0.76). |
| **Neural Net (NN)** | Полносвязная нейросеть (50→64→16→1) — вспомогательный прогнозист (вес ≈ 0.24). |
| **Ridge meta-learner** | Линейная модель-«судья», взвешивающая прогнозы LGB и NN в один итог. |
| **Feature (признак)** | Числовая характеристика объекта, подаваемая на вход модели. Всего 55. |
| **User input** | 11 характеристик, вводимых пользователем вручную (см. раздел 5). |
| **Derived feature** | Признак, вычисляемый автоматически из user input (гео-, макро-, домовые признаки). |
| **REGION** | Целочисленный код региона/района, полученный из координат (сетка 0.01°). |
| **segment_code** | Код микро-сегмента рынка (полигоны районов), в который попадает точка. |
| **OSM distance** | Расстояние до ближайшего POI (аптека, больница, детсад, крупная дорога) из OpenStreetMap. |
| **Stat / Macro features** | Региональная макростатистика: зарплаты, ИПЦ, объёмы строительства, население и т.п. |
| **BLP (Building Last Price)** | Последняя известная цена по конкретному дому (панельная история объявлений). |
| **BFE (Building Fixed Effect)** | «Премия дома» — регуляризованная (shrinkage) поправка на конкретное здание. |
| **price_index** | Квартальный индекс цен (база 2025Q4 = 1.0) для приведения цен к текущему периоду. |
| **price_index_current** | Значение индекса на текущий квартал; переводит «реальную» цену в номинальную. |
| **momentum / trend** | Динамика индекса цен: 3 мес., год к году (YoY), отклонение от 5-летнего тренда. |
| **region calibration (α)** | Мультипликативная пост-коррекция прогноза по региону (окно Янв–Фев 2026). |
| **shrinkage** | Сжатие оценки к среднему при малом числе наблюдений (борьба с переобучением на редких домах). |
| **confidence band** | Доверительный интервал ±10% вокруг прогноза (уровень 90%). |
| **livability / proximity** | UI-показатели «комфорта» и близости инфраструктуры (не влияют на цену). |

## 3. Описание (Description)

**hpwhd** — веб-сервис на FastAPI, который принимает 11 характеристик квартиры,
автоматически достраивает их до 55 признаков и возвращает оценку стоимости в тенге.

Основной поток:

1. Пользователь вводит 11 параметров (координаты, площадь, этаж, состояние,
   материал, год постройки и т.д.).
2. `FeaturePipeline` детерминированно собирает 55 признаков: гео-код региона,
   код сегмента, расстояния до POI, региональную макростатистику, историю дома,
   индекс цен.
3. Ансамбль `LGB + NN → Ridge` предсказывает `log(цена/м²)` в ценах базового
   квартала (2025Q4).
4. Результат переводится в номинальные цены текущего квартала через
   `price_index_current`.
5. Применяется региональная калибровка α (пост-коррекция по свежему рыночному окну).
6. Цена/м² × площадь = **итоговая стоимость в KZT**, плюс доверительный интервал ±10%.

Дополнительно UI показывает «портрет локации»: близость аптек/больниц/детсадов/дорог,
индекс комфорта и разбивку факторов цены (площадь, локация, состояние и т.д.).
Эти показатели **справочные** и на прогноз цены не влияют.

**Точность:** Test MAPE 9.64%; на «живых» объявлениях марта–апреля 2026 — 12.12%
(56.9% прогнозов в пределах ±10%, 84.3% в пределах ±20%).

## 4. Концепт (Concept & Architecture)

### 4.1 Ансамблевая идея

Ни одна отдельная модель не идеальна, поэтому используется **стекинг**:

```
        11 user inputs
              │
              ▼
      FeaturePipeline ── собирает 55 признаков
      • city_encoder.json   (lat/lon → город, KNN)
      • region_grid         (снап 0.01° → REGION)
      • segment polygons    (микро-сегмент рынка)
      • OSMDistances        (сетка 6.6M ячеек → расстояния до POI)
      • StatLoader          (региональная макростатистика)
      • BLP / BFE lookups   (история и премия дома)
      • price_index         (квартальный тренд + momentum)
              │
              ▼
        NNInference
     ┌───────────────┐
     │ scaler_X       │  QuantileTransformer
     ├───────────────┤
     │ LightGBM  ─────┼─► lgb_log ┐
     │ Neural Net ────┼─► nn_log  ├─► Ridge meta → ensemble_log
     └───────────────┘            ┘
              │
     exp(ensemble_log) × price_index_current   → номинальная KZT/m²
              │
     × region α (калибровка)                    → скорректированная KZT/m²
              │
     × площадь (TOTAL_AREA)                      → ИТОГОВАЯ ЦЕНА (KZT)
              │
     ±10% confidence band
```

### 4.2 Целевая переменная (target)

Обучение велось на `log(asking_price_real)`, где
`asking_price_real = price_per_sqm / price_index[quarter]` (база 2025Q4 = 1.0).
Такое «дефлятирование» убирает влияние времени публикации, а обратное
преобразование `exp(pred) × price_index_current` возвращает цену текущего периода.

### 4.3 Веса ансамбля

| Компонент | Вес | Роль |
|-----------|-----|------|
| LightGBM | ≈ 0.764 | Основной прогнозист (табличные признаки, нелинейности) |
| Neural Net | ≈ 0.236 | Вспомогательный прогнозист (сглаживание) |
| Ridge intercept | ≈ 0.004 | Смещение мета-модели |

### 4.4 Архитектура нейросети

```
Linear(50 → 64) → ReLU → Linear(64 → 16) → ReLU → Linear(16 → 1)
```
Вход масштабируется `scaler_X` (QuantileTransformer), выход NN обратно
преобразуется `scaler_y` (StandardScaler по log-цене).

### 4.5 Пост-обработка: калибровка по регионам

После прогноза применяется мультипликативный коэффициент α по региону
(`data/region_calibration.json`), обученный на leakage-free окне Янв–Фев 2026
методом `median(actual / pred)`. При малом числе наблюдений (< 100) α сжимается
к 1.0 (shrinkage), чтобы редкие регионы не давали шумную коррекцию.

## 5. Входные данные (User Inputs)

Пользователь вводит **11 характеристик**. Валидация — Pydantic (`main.py`).

| Поле | Тип | Диапазон | Описание |
|------|-----|----------|----------|
| `ROOMS` | int | 1–20 | Число комнат (собирается, но не в списке признаков модели) |
| `LONGITUDE` | float | 46.0–87.0 | Долгота (WGS-84) |
| `LATITUDE` | float | 40.0–55.0 | Широта (WGS-84) |
| `TOTAL_AREA` | float | 0–1000 | Общая площадь, м² |
| `FLOOR` | int | 1–100 | Этаж квартиры (используется только в UI-факторах) |
| `TOTAL_FLOORS` | int | 1–100 | Этажность дома |
| `FURNITURE` | int | 1–3 | 1 = без мебели, 2 = частично, 3 = с мебелью |
| `CONDITION` | int | 1–5 | 1 = черновая … 5 = свежий ремонт |
| `CEILING` | float | 1.5–10.0 | Высота потолков, м |
| `MATERIAL` | int | 1–4 | 1 = другое, 2 = панель, 3 = монолит, 4 = кирпич |
| `YEAR` | int | 1900–2030 | Год постройки |

Все остальные 44 признака **вычисляются автоматически** и не требуют ввода
(нет ручных fallback'ов «среднее/медиана/NA» в горячем пути).

## 6. Группы признаков (55 features)

| Группа | Кол-во | Примеры |
|--------|--------|---------|
| User inputs (в модели) | 9 | `LONGITUDE`, `LATITUDE`, `YEAR`, `CONDITION`, `TOTAL_FLOORS`, `FURNITURE`, `CEILING`, `MATERIAL`, `TOTAL AREA` |
| Geographic | 2 | `REGION`, `segment_code` |
| City | 2 | `is_almaty`, `city_target_enc` |
| OSM distances | 4 | `dist_to_pharmacy_km`, `dist_to_hospital_km`, `dist_to_kindergarten_km`, `dist_to_main_road_km` |
| Stat / Macro | 26 | `srednmes_zarplata`, `index_real_zarplaty`, ИПЦ-индексы, объёмы строительства, население |
| Panel (история дома) | 4 | `building_last_known_price`, `months_since_building_last_listed`, `building_listing_count_historical`, `building_price_volatility` |
| Price index | 4 | `price_index_current`, `index_momentum_3m`, `index_momentum_yoy`, `index_vs_5yr_trend` |
| BFE | 1 | `building_fixed_effect` |
| v2 (новые) | 3 | `floor_ratio`, `building_age`, `is_old_panel` |

**Топ-факторы по важности (LGB):** `building_last_known_price` (история цены дома),
`city_target_enc` (город), объёмы нового строительства, координаты, `YEAR`,
`CONDITION`, `CEILING`.

## 9. Встраивание в приложение банка (Integration)

**Способ поставки:** контейнер Docker (`Dockerfile`, `docker-compose.yml`),
Python 3.11-slim + геопространственные зависимости; PyTorch — CPU-only.

**Рекомендации по интеграции модуля:**

- Использовать `/predict` как внутренний REST-эндпоинт (сервис-к-сервису), а
  банковский фронтенд/BFF вызывает его и отображает цену и доверительный интервал.
- Кэшировать/предзагружать артефакты при старте (модель грузится один раз в
  `lifespan`), делать readiness-проверку через `/health`.
- Учесть Git LFS: `distance_grid.parquet` (196 МБ) обязателен для расчёта
  расстояний до POI.
- Ключ `YANDEX_MAPS_API_KEY` опционален; без него карта откатывается на Leaflet/OSM.

**Важно для банковского контекста:**

- Прогноз — **ориентировочная рыночная оценка**, а не официальная оценка залога;
  показывать доверительный интервал и дату актуальности данных.
- Индекс цен и калибровка датированы (база 2025Q4, окно калибровки Янв–Фев 2026) —
  требуется регламент периодического переобучения/обновления справочников.
- Обеспечить логирование входов/выходов для аудита и мониторинга дрейфа модели.

## 10. Ограничения и планы (Limitations & TODO)

- Покрытие — жилые квартиры Казахстана; коммерческая недвижимость и частные дома
  вне зоны обучения.
- Качество зависит от свежести истории объявлений по дому (BLP) и региональной
  статистики.
- Индекс цен и региональная калибровка требуют регулярного обновления
  (перезапуск обучающего пайплайна).
- Дальнейшие направления: расширение истории сделок, добавление мониторинга
  дрейфа, регламент переобучения, дообогащение POI-признаков.
